# ガイナ様向け 結線表作成アプリ

## 目的と起動

`/` と `/wiring/` に既存の3段階アプリを拡張した。図面を取り込む → 結線表の下書きを確認・修正 → Excel出力。既存の仕入・相見積 `/procurement/` は維持。

Node.js 22以上で `npm ci` → `npm run dev`。起動したローカルURLの `/wiring/` を開く。静的配信だけなら `npm start`（Python 3が必要）。Netlifyは既存の `npm run build` / `dist` 設定で動作する。**APIキー・外部OCR契約・サーバー設定は不要**。PDF.js、Tesseract.js、英数字モデル・WASMをビルドで同梱する。初回OCRはモデル読込に時間がかかる。

入力はPDF（100ページ・40MBまで）、PNG/JPEG/WebP（40MB・6000万画素まで）。画像は表示・OCR用PDFにブラウザー内で変換する。書式Excelは任意（20MBまで）。添付原本・抽出値・実案件ファイルは公開アセットやサンプルに含めていない。

## 操作と実装機能

- 図面なしの手入力から開始可能。機器記号と電線種類を別項目で管理。同じ機器に複数の独立したケーブルを作れる。
- 機器名、場所・MARK、相手先、電線種類、サイズ、設定芯数、シールド3状態、備考、ページ、図番、追加参照を編集。
- 芯ごとに色・芯番号、線番号、チューブ番号、端子、未確認／要確認／確認済みを編集。
- 線番号をチューブ番号の初期候補にする。連動中は線番号の修正を反映。チューブを直接変更した後は独立し、必要なら「線番に戻す」で連動に戻せる。
- 全識別子は文字列。先頭ゼロ・ハイフンを数値変換しない。同じ線番号の複数芯を統合・削除しない。
- 種類・サイズ・色・チューブ表記のdatalist候補と自由入力。候補管理で登録・編集・削除。登録しただけで結線を確定しない。
- 芯線の追加・削除・上下移動。設定芯数までの追加は明示操作のみで、余分な芯を自動削除しない。
- ケーブル複製は機器名・線番号・チューブ番号の再確認メッセージと要確認状態を付ける。シールドは通常芯線の配列から分離し、専用の線番号・チューブ・接続先を編集する。
- 左に図面、右に編集表。項目を選ぶと元ページ・範囲へ移動・拡大。図面全体にも戻れる。機器名・線番号・チューブで検索し、未確認・要確認に絞れる。
- 図面上をドラッグして実OCRを実行。文字候補を機器・線番号・端子などに利用者が対応付ける。文字だけ読めたものを電気的接続として自動確定しない。
- 編集後は自動でこの端末のIndexedDBに保存。保存ボタンもあり、前回の続きから入力値・図面・書式・候補・OCR候補を復元。保存は現在の1プロジェクト。クラウド同期ではない。
- 再読取では手修正・確認済みの値、独立したチューブ表記を上書きしない。差分は保留候補として表示。利用者が削除した芯・ケーブルの自動復活も防ぐ。削除は直前の操作を戻せる。

## 資料確認とExcel対応

受領したExcelの主対象CP-2は、A:B No、C:F MARK、G:K機器、L:R電線種類、S:AV最大10芯の横並び、AW:BA相手先。色と線番号を2行単位で重ね、一部の機器はさらに端子等の段を持つ。ブロック長は原本で4／6／8行等が混在する。原本全項目に図面抜粋が対応するわけではない。

新規出力は6行を1ブロックとして色・線番号・端子を2行ずつ重ねる。11芯以上・シールド追加分は次のブロックに続ける。元のレコードを機器名一致で自動更新しない。

| 入力項目 | 横並び結線表への出力先 | 補足 |
| --- | --- | --- |
| No | A:B | ケーブル順。識別子の数値化ではない |
| 場所・MARK | C:F | ケーブル単位 |
| 機器名・機器記号 | G:K | 電線種類と分離 |
| 電線種類・サイズ・設定芯数 | L:R | 仕様を改行して表示 |
| シールド有無 | L:R | 未設定は推測で記入しない |
| 図番・ページ | L:Rと専用明細 | 手入力の参照も保持 |
| 芯の色・番号 | S:AVの上段 | 10芯まで横並び |
| 線番号 | 同じ芯列の中段 | 重複する線番も保持 |
| 接続先端子 | 同じ芯列の下段 | 不明は空欄 |
| 相手先 | AW:BA | 自動で盤名を補完しない |
| チューブ番号 | チューブ・端子明細 | 元様式に専用欄がないため独立列。線番号や端子を上書きしない |
| シールド表記・接続先 | シールドとして独立した横並び欄と専用明細 | 設定芯数の通常芯線に含めない |
| 備考・確認状態・入力元・読取根拠・追加参照 | チューブ・端子明細、読取根拠／出力条件 | 元の文字・位置・経路、利用者指定を記録 |

**書式Excelを選んだ場合**、CP-2の列幅・元セルスタイルを参照し「結線表_CP-2」「チューブ・端子明細」「出力条件」を新規追加した別ファイルを作る。元CP-2を含む既存全シート・画像・スタイル等のパーツはそのまま保持。追加に必要なworkbook.xml、リレーション、Content Typesだけにメタデータを追記する。元ファイルは変更しない。同名の新規シートがあれば連番にする。

**書式Excelなし**でも同じ列配置の新規Excelと専用明細・読取根拠を出す。原本の全装飾を複製したものではない。

横向き、横1ページ、対象範囲、見出し反復、罫線・結合を設定。書式追加モードは8ブロックごとに改ページし、機器ブロック途中でのページ分断を避ける。長い備考は専用明細に出力する。Excelデスクトップの印刷プレビュー・実プリンターでは未検証。

## 自動読取の実装・検証範囲

PDF.jsから線・機器枠・端子円・円形機器・黒い接続点を抽出。元PDFに文字があれば優先し、ない場合は同梱Tesseract.jsで実OCR。細いCAD数字は、接続成分・穴の数と位置・一般的な0〜9のストローク形状も画像比較する。期待値の機器名や線番はアプリ側に固定していない。

円形機器は接続した水平線・破線を辿り、端子円と直角の折り返しを経由して線番号を読む。交差の両方が途中の場合は接続せず、両端点が合う曲がり角または黒い接続点がある箇所だけをつなぐ。小さい円周のCAD近似誤差を許容する。矩形機器は機器端子から外側の端子円までの同一直線の配線を検証し、線に対応する文字を候補にする。単なる文字間距離だけでは対応付けない。

PLCアドレスらしいY表記は線番号へ自動採用せず保留する。OCRの文字欠落・別表記のPLCアドレスは完全には識別できない。元の読取値と処理根拠を残すので照合が必要。

受領PDF7ページ（E-15）の指定4機器・各2線番号は、PDFのみを入力する実行で8/8一致を検証。原本Excelは抽出完了後の出力書式にだけ渡す。電線種類と色が空欄であることも確認。**これはE-15全ページや他図面の正答率を示すものではない。** 他の機器名・線番には誤読が残る。

スキャン画像PDF・画像は実OCRで文字候補を作れるが、画像から機器・接続経路を全自動認識する処理は未実装。現状は範囲OCR＋利用者による対応付けを使う。和文OCR、任意形状・斜線・複雑な交差、他ページへの電気的な接続追跡は未対応。追加参照を記録するデータ項目と元ページ情報は備えるが、ページをまたぐ結線の自動確定はしない。

図面から確定しない種類・サイズ・色・シールド・盤名は空欄／未設定。利用者が候補やルールで指定する。自動候補はすべて要確認。確認済み操作は利用者の照合記録であり、機械精度の保証ではない。

## テストと受入確認

- `npm test`：既存業務テストに加え、チューブ独立、文字列保持、複製、重複線番保持、再読取保護、候補CRUD、交差と曲がり角、書式保持、シールド出力、11芯以上の折り返しを検証。
- `npm run check` / `npm run build`。
- `npm run test:wiring-browser`：手入力からの編集・保存復元・候補管理・Excelダウンロード、架空PDFの実読取と再読取保護、元図面復元、左右配置、モバイル、実スキャン画像OCRと文字候補の適用、外部ファイル送信なしを検証。
- `npm run test:rfq-browser`：既存の相見積への影響確認。
- 実資料の検証は `npm run verify:wiring-e15 -- /path/drawing.pdf /path/template.xlsx /path/output`。Chromiumが必要（`CHROMIUM_PATH`で変更可）。期待値は検証スクリプトのassertにのみあり、本体読取へ渡さない。出力先に実案件データを作るため公開ディレクトリーを指定しないこと。
- 書式出力は全既存パーツをバイト比較し、既存全ワークシート・画像・スタイル・共有文字列が変わらないことを検証。ExcelJSで新規シートの結合セル・文字列・チューブ明細・印刷範囲を再読込確認。

## 保存と運用上の範囲

ファイル・抽出データはブラウザー内処理で外部API送信なし。保存はこのブラウザーのIndexedDB。ブラウザーデータ削除・端末変更・公開URL変更では引き継がれないのでExcelも出力する。複数ユーザー共有、クラウド同期、会社別ログイン、案件一覧の複数保存は今回の対象外。同一プロジェクトは図面1ファイル（複数ページ可）。別の図面で新規作成する場合は、保存／Excel出力後に新規作成を使う。
