# ガイナ 仕入・相見積 — 実装・引渡しメモ

2026-11-05。お客様提供「開発指示書 改訂版2.0」の項目に対応。公開画面は `/procurement/`。この版は単独利用の業務プロトタイプです。

## 今回の画面

- 依頼：資料取込 → 明細確認 → 依頼条件 → プレビューの4ページ。工程単位で入力・保存。
- 比較：品目×仕入先の表を主領域、右側に根拠付き提案／確認済みデータへの質問。小さい画面では上下に再配置。
- 採用：品目・仕入先別内訳と確認チェック → 確定。確定後は発注明細／納品請求／交渉結果／採用版のタブ。
- サンプル／自分のデータを別DBキーで管理。自分のデータは空から開始し、サンプル価格を補完しない。
- 以前の簡易デモは `simple-demo.html` に保存。従来の保存領域や実連携画面 `workspace.html` は変更しない。

## 保存

IndexedDB `gaina-rfq-v2` の `workspaces` と `files` を使用。ブラウザの再読込・タブを閉じても復元する。書込み時は同じトランザクションで保存版を検査し、別タブの古い版による更新は拒否する。

### 主な保存項目

- 会社ID（現在は単一会社 `gaina`）、案件、現場名・担当・納入先。
- 依頼ID／番号／版／状態、明細ID、原文型番・正規化型番、メーカー・仕様・数量・単位・確認者・日時。
- 回答先、期限、希望納期、送料分納条件、備考。依頼書の内容スナップショット。
- 仕入先ごとの回答版、旧回答、単価・数量・単位・納期・期限、仕様一致・回答確認。
- 送料方式（固定／金額条件付き免除）、分割適用可否、値引き・分割適用可否。
- 選択組合せ、固定比較基準とその品目・数量範囲。
- 採用の旧版・新版、商品・値引き・送料・合計、案件別予定原価・納入条件。
- 根拠付き提案、価格版、未成立試算、依頼文下書き、案件別需要、採否理由・成立単価。
- 納品・請求行、採用版ID、数量・単価・送料、承認済み変更額と理由、実納入日・遅延理由、照合結果と全明細照合後の実購入原価。
- 当時定価付き購入履歴、期間付き定価履歴、価格改定の発表日・適用日・基準・根拠。
- 電線の種類・サイズ・芯数・購入形態・適用銅ベース。過去基準が不明・異なる電線単価はR02の試算から除外。
- 原本ファイル（Blob）、名前・種別・SHA-256・取込状態・確認日時・行参照。
- 操作履歴（直近500件）。JSONバックアップ／同じデータ区分への復元。

ブラウザデータ消去で失われるため、実運用のサーバーDB・バックアップの代替ではありません。JSONバックアップは取引データで、原本Blobを含みません。他端末へ復元すると原本の再追加が必要です。

## 原本・読取

|形式|対応|
|---|---|
|XLSX|先頭シートを実際に読み、列の対応・原本行の確認後に取込|
|CSV|UTF-8／Shift-JIS、列対応、エラー行を分離|
|PDF|原本保存・ブラウザPDF表示。ページ操作はブラウザ標準ビューア|
|PNG/JPEG|原本保存・画像表示・カメラ入力|
|PDF/画像のOCR|未接続。候補を捏造せず手入力を案内|
|図面数量の自動計測|未接続。数量・仕様の手動確認が必要|

原本は1ファイル10MB、表取込は1000行以内、依頼は100明細まで。依頼取込では品名・数量・単位を検証し、確認前の行を依頼確定に進めません。回答取込では型番の対応行を選び直せます。数量・単位差・単価×数量と明細金額の不一致は取込エラーにします。回答行の仕様と確認状態は、原本照合後に利用者が確定します。

## 計算と確定

- 金額は税抜・小数2桁で丸め、数量は小数入力に対応。消費税・税区分をまたぐ端数の自動照合は未対応。
- 選択総額＝商品合計−値引き＋仕入先ごとの送料。送料を品目数で重複加算しない。
- 一括の送料・値引きを分割へ適用するには確認フラグが必要。不明な送料は0円にしない。
- 有効期限・仕様・数量・単位・回答確認・希望納期を確認。未回答は0円回答と区別。
- 送料込み最安探索は有効な組合せを最大100,000通り列挙。完了時だけ厳密な最安、未完了は最安候補。同額なら納期、仕入先数を優先。
- 固定比較基準は選択の変更で動かない。品目・仕様・数量・単位変更後は基準も再確認。
- 対応する販売単価を全品目で確認できる範囲のみ、材料粗利額・率を計算。未連携・売上0円は未算出。
- 確定の二重操作で採用版・予定原価を二重作成しない。変更時は旧版を保持する。
- 未成立の16,000円などの交渉余地は採用額から引かない。同時成立を確認していない効果は合算しない。
- 発注書は仕入先別。数量は案件・明細に紐付けて保持。Excel／CSVでは仕入先単位の送料・総額を先頭行のみに置く。
- 依頼作成・採用確定は実送信をしない。外部で依頼した履歴は手動で記録する。

## 判定ルールと設定値

|ルール|今回の動作・入力条件|
|---|---|
|R01 追加依頼|比較勝敗付き履歴が既定3件以上ある場合に集計。通常の単価履歴だけで最安傾向を推測しない。比較勝敗データの入力UIは未対応|
|R02 数量条件|同型番・仕様・単位、確定した次案件の納期差30日以内。案件別数量を保持した再見積下書きと今回分の効果試算|
|R03 同等品|適合・承認履歴がある場合に確認候補。自動置換なし。仕様承認ワークフローの専用UIは未対応|
|R04 納期|今回納期不足を検知。過去の約束・実績データが3件以上あれば遅延を集計。追加費用の確率推測なし|
|R05 材料粗利|対応売価が確認済みで、同範囲の類似売価付き履歴3件以上に対し中央値より5pt以上低い場合。提出済み単価の変更承認を案内|
|R06 差額|発注行と累計納品請求を照合。1円以上の未説明差額。承認済み本体・送料変更を別に控除し、仕入先単位の請求値引きも照合。分納不足を勝手に差額扱いしない|
|R07 成立条件|同仕入先・品目・仕様・近い数量の成立結果を参照。R02と重なると抑制。成立済み結果の上書き禁止|
|R08 価格改定|適用前60日以内、該当する使用予定あり、確認済み改定案内。定価改定から仕入影響額を推測しない|
|R09 送料|今回の分割送料が未確認の場合に確認依頼。過去免除だけで0円にしない。詳細な配送便・数量閾値履歴の自動照合は未対応|

履歴期間12か月、数量帯は再見積対象数量±20%、最大表示3件。参照月数・最小件数・納期差・粗利差・改定前日数・差額閾値・表示件数は管理画面から変更可能です。期限→不足条件→試算可能→その他の順に表示します。根拠や履歴が不足している場合は提案を水増ししません。

「データに質問」は確認済み履歴・回答・次案件からの定型回答です。汎用生成AI・自然言語検索サービスではありません。過去価格／数量交渉／送料以外の質問には不足情報を返します。根拠と会話は保存します。

## 未接続・本番化が必要な範囲

会社別ログイン・サーバー側の会社ID／閲覧編集確定権限、クラウド原本共有、サーバー側の採用検証と複数端末トランザクション、メール／発注送信、外部案件DBへの予定原価同期、AI/OCR、公式価格の自動収集は本画面では未接続です。従来の `workspace.html` と既存Netlify APIは残し、この新画面へ未検証で直結していません。ローカル会社IDは認証・テナント分離の代替ではありません。

R03の承認、R08の仕入価格改定単価と回避額、配送便単位の複雑な分納送料、税率・端数を含む会計レベルの請求照合は、実業務のデータ・接続先と合わせた追加実装が必要です。ボタンだけで対応済みとは表示しません。
