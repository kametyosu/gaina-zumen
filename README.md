# GAINA 業務管理

## 公開画面

- `/procurement/`：設定不要の操作デモ。商材を選ぶ → 見積を比べる → 送料込み最安を採用する。
- `/proposal/`：お客様向けの簡潔な6ページ提案資料。
- `/proposal/gaina-proposal.pdf`：配布用PDF（A4横・6ページ）。
- `/`：配線指示書の編集・CSV出力・職人用帳票。
- `/procurement/workspace.html`：従来の実連携ワークスペース。
- `/supplier/#専用トークン`：実連携版の代理店回答ページ。

## 現在のデモ

主画面から説明・年間計算機・FAQを外し、3社の見積と3つの次の一手に絞っています。デモの採用対象は **回答済み見積の送料込み総額の最安** です。在庫・納期は参考表示し、最安選定では除外しません。`lowestQuotes` が現在の選定処理で、旧機能向けの `ranked` は別に残しています。

「次の一手」は表示中の商材の過去実績から単価・送料・掛け率の交渉目安を出し、成立時の材料粗利額・率の追加改善を試算します。別商材への誘導はしません。電線の履歴は仕入日・購入量・当時の銅ベース（円/t）・仕入単価（円/m）を表示します。照明・盤は品番、数量、当時の定価・掛け率を表示します。

図面・金抜き明細の選択からサンプル商材を表示し、一括依頼・代理店回答を体験できます。**実ファイル解析・外部送信・実在庫照会はしません。価格・銅建値・取引履歴はすべて架空です。** デモは `gaina-simple-demo-v5` に保存され、実連携の保存領域は変更しません。履歴の商材切替では編集中の見積を上書きしません。

## データと提案資料

`procurement/analysis-data.mjs` の商材データを比較シナリオ・提案資料で共用します。`profitAction` が同一メーカー・品番、過去1年、数量0.5〜2倍の履歴から交渉目安を算出します。電線の単価は同じ銅ベースの履歴のみ比較します。`demo-domain.mjs` の電線履歴には、各購入日の架空の銅ベースを記録しています。

提案資料は「過去の仕入履歴 → 送料込み最安を採用 → 同じ商材の利益を改善」の6ページです。年間材料仕入2,000万円・全額10%削減・対応売上2,500万円の仮定も資料内に残しています。無料試行は2026年内、継続相談は2027年1月という提案です。実施条件は別途合意し、成果や料金を保証しません。

履歴単価と同時点の通常見積の比較基準は別に扱います。実際の削減額は同条件の基準と実購入額から確認します。異なる時期の単価差や、銅価格の下落をそのままサービス成果にはしません。

## 起動・検証

Node.js 22以降、npmを使用します。

```sh
npm ci
npm test
npm run check
npm run build
npm start
```

`npm start` はビルド後、Python 3で3000番ポートの静的プレビューを起動します。デモ・提案資料はAPIなしで動作します。

`npm test` はドメイン・API・収集・デモ・分析の49ケースを実行します。実ブラウザでは最安選定、採用、銅ベース付き履歴、履歴閲覧時のデータ保持、一括依頼、モバイル表示、提案PDFの保存を確認しています。

```sh
# HTMLの再生成（通常のbuildでも実行）
node scripts/render-proposal.mjs
# PDFの再生成。Chromiumが必要
CHROMIUM_PATH=/usr/bin/chromium npm run proposal:pdf
npm run build
```

PDF生成は全ページのフッターへのはみ出しを検査します。PDFはリポジトリへ保存し、Netlifyでは再生成せずコピーします。提案内容を変更したらPDFも更新してください。

## Netlify公開

`netlify.toml` は `npm run build` と `dist/` の公開を設定しています。`main` への更新で既存サイトを自動デプロイする想定です。公開デモと提案資料には管理キーが不要です。

公開先へのアクセスは実行環境の通信制限で拒否されることがあります。ローカル検証とGitHubへの反映を、本番デプロイ成功・本番表示確認とは区別してください。

## 従来の実連携機能

`/procurement/workspace.html` はNetlify Functions・Blobsを使います。利用する場合はNetlifyのFunctionsスコープに24文字以上のランダムな `GAINA_ADMIN_KEY` を安全に設定して再デプロイし、画面から同じキーで接続します。キーをチャット・コードへ記載しないでください。

`npm run dev` はループバック3001番ポートにAPIと公式Blobsエミュレーターを起動します。ローカル専用キーは `local-development-only-administrator` です。本番では使用禁止。保存先は `/tmp/gaina-local-blobs`（`GAINA_DEV_DATA_DIR`で変更可）。エミュレーターのGETに不足するETagをLISTから補い、条件付き更新は維持します。

実連携版には代理店別URL・期限・失効、回答確認、CSV/XLSX履歴取込、価格改定予約と銅記録があります。定期収集は本番で毎日9時・15時（日本時間）。公式取得元の設定・実取得の検証が必要です。単一組織・共有管理キー・1クラウド案件の想定で、個人別権限や複数案件DBは未対応です。

配線指示書は手動編集・サンプル図面との位置連携・確認済みCSV・施工/照合欄付き帳票に対応。実図面の自動OCR・接続解析は未実装です。

## 同じ商材の利益改善を示す次の一手

現在の最安見積を起点に、同品番の過去単価・掛け率・送料から交渉目安を試算します。今回より良い過去条件がなければ追加改善は0円とし、見込みを作りません。送料不明の履歴を送料0円と扱うこともありません。

3項目は「近い数量の単価・掛け率」「数量帯ごとの条件」「付帯費用の照合」です。電線はメーカー・種類・サイズ・芯数・切売り条件・適用銅ベースが一致する履歴を使います。照明は同品番・同仕様と当時の定価から掛け率を計算します。単価案は過去1年・数量±20%の中で最も近い数量を優先し、数量帯案は今回より多く1.5倍以内の実績を別試算にします。3案は合算しません。

例：CV 3.5sq × 3Cの今回見積は445円×1,200m＋送料6,000円＝540,000円。過去の同数量・同銅ベース126万円/tで430円/mの実績から、送料を据え置き522,000円を交渉目安にし、追加粗利18,000円、25.0%→27.5%と試算します。1,500mの数量帯案は追加300mの用途がある場合だけ検討し、同じ1,500m同士で比較します。送料は過去も今回も6,000円なので付帯費用の追加改善は0円です。切断・梱包費を含め、回答を編集すれば比較表と3案を同時に再計算します。元の見積・採用額は変更しません。

提案PDFの4ページ目も同じ根拠・金額で更新しています。過去と数量・時期・条件が完全に同じとは限らず、交渉成立や効果を保証しない架空デモです。
