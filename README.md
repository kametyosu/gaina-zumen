# GAINA 業務管理

結線図からの配線指示書と、照明器具・盤・資材の相見積管理を行うWebアプリです。

- `/`：配線一覧の編集、確認済み管理、職人用指示書、CSV・PDF出力
- `/procurement/`：設定不要の体験デモ。お客様分析 → データで改善 → アプリ運用
- `/proposal/`：お客様向け9ページ提案資料。HTML閲覧・印刷・PDFダウンロード
- `/proposal/gaina-proposal.pdf`：配布用PDF（A4横・9ページ）
- `/procurement/workspace.html`：従来の実連携ワークスペース（クラウド設定が必要）
- `/supplier/#専用トークン`：代理店の見積回答ページ

## 起動・検証

Node.js 22以降、npm、静的プレビューにはPython 3を使用します。

```sh
npm ci
npm test
npm run check
npm run build
npm run dev
```

`npm run dev` はループバックの3001番ポートで、Netlify Blobsの公式ローカルエミュレーターとAPIを起動します。ローカル検証専用の管理キーは `local-development-only-administrator` です。この固定値は開発サーバーだけで使い、本番では絶対に使わないでください。保存先は `/tmp/gaina-local-blobs`（`GAINA_DEV_DATA_DIR`で変更可能）。SDKエミュレーターがGETでETagを返さないため、ローカルだけLISTからETagを補います。条件付き書込の検証は維持します。

`npm start` はビルド後、3000番ポートで静的ファイルだけを配信します。比較・履歴分析は利用できますが、回答受付と定期収集は開発APIまたはNetlify Functionsが必要です。

## かんたん相見積デモ

`/procurement/` は外部連携なしで体験できます。管理キー・公式取得元・Excelファイルの用意は不要です。旧ワークスペースのデータには触れず、デモの操作は `gaina-simple-demo-v1` に保存します。

- 主画面は3社の比較表と、仕入総額・全数納入の可否・自社の過去掛け率の目安に絞ります。材料粗利・改善額は選定欄とレポートへ表示します。
- 照明・盤・電線の架空案件を選択可能。納期5日以内の条件に切替すると候補を再計算します。
- 依頼フォーム → 回答待ち → サンプル回答、または代理店側の回答入力を体験できます。送信・メール・実URL発行は行いません。
- 過去掛け率の根拠・集計条件、値上げ・銅変動の影響を必要時にダイアログで表示。
- 採用前後の材料粗利をレポートで比較し、印刷・PDF保存できます。工賃・共通経費を含む営業利益ではありません。
- 既存の実連携機能は `workspace.html` に残し、デモ画面のナビゲーションには露出しません。

サービスの方針は「依頼を一度にまとめる」「同一条件で比較する」「改善額と次の行動を提示する」です。多数の台帳を日常画面に並べず、価格履歴・市況情報は案件に関係する提案に集約します。最安だけを自動採用せず、納期を含めて人が選定します。

### 資料起点・在庫納期・自社掛け率のデモ

図面・金抜き明細のファイル選択・ドロップ、サンプル資料の選択から、照明・盤・電線の3商材が並ぶ流れを体験できます。**実ファイルの内容は解析せず、固定のサンプル商材を表示します。** ファイル名を表示し、資料内の根拠ページと数量照合のイメージを示します。図面の仮数量は確認するか、依頼対象から外す必要があります。金抜き明細では追加の確認ステップを設けず、対象商材と数量をそのまま一括依頼できます。

一括依頼後は「対象商材」から切替可能。各商材の価格・在庫・回答・選定を個別に保持します。利益レポートは選択中の商材が対象で、案件全体の集計ではありません。デモデータは `gaina-simple-demo-v3` に保存し、従来の実連携データは変更しません。

在庫数だけでなく、不足分を含めた全数の納入日を判定します。最安のA社でも必要日までに全数がそろわなければ採用候補から外します。実際の在庫照会・入荷保証は行いません。

過去掛け率は自社のサンプル履歴に基づく目安です。同一メーカー・型番、数量0.5〜2倍、固定のデモ基準日2026-11-05から過去1年で比較し、当時の定価が分かる履歴のみで範囲と中央値を計算します。定価不明の履歴は単価を残したまま掛け率集計から除外し、3件未満の価格帯は表示しません。市場全体の相場とは表示しません。

### お客様分析と提案資料

入口の「お客様の仕入分析」では、架空の電気工事店の2026年5〜10月の履歴を表示します。仕入総額2,400万円、電線60%、電線6サイズの価格帯・参考単価と改善余地を提示し、選択した商材の相見積へ進めます。

データの出典は `procurement/analysis-data.mjs` で統一。デモ画面・比較シナリオ・提案書の計算に共用します。分析参考単価と相見積の送料込み単価が一致することをテストしています。実在庫・公式銅建値・市場全体の相場ではありません。

- 改善余地：同数量を参考条件で再購入した場合の131万円。実際の削減ではありません。
- 購入後の効果例：請求照合済みを想定した架空5件で削減17.9万円、材料粗利75.3万円→93.2万円、20.0%→24.8%。対応売上は376.5万円。
- 改善余地と確定例は数量・段階が異なるため合算しません。無料試行中の成果課金や工賃・共通経費込みの利益保証も行いません。

`/proposal/` には「お客様分析→電線・照明・盤の改善例→運用→年内無料試行→年明け継続相談」を説明する9ページの提案書を配置します。金額・建値・実績は架空であることを各ページに明示します。具体的な有料料金は未確定として、年明けの別途合意にしています。

```sh
# HTMLをデータから再生成（通常のbuildでも実行）
node scripts/render-proposal.mjs
# PDFを再生成。Chromiumが必要。環境に応じCHROMIUM_PATHを設定
npm run proposal:pdf
# 更新PDFを含めて公開用distを構築
npm run build
```

配布PDFはリポジトリに保存します。データ・提案書の変更時はPDFも再生成してください。PDF生成は全ページのフッターへのはみ出しを検査します。NetlifyのbuildはChromiumを必要とせず、生成済みPDFをコピーします。

## Netlifyへの配置

`netlify.toml` がビルドコマンド、`dist/` の公開、Functions、定期実行を設定します。公開ディレクトリにはサーバーソースや依存パッケージを含めません。`dist/` 自体はGitに含めません。

1. Netlifyでこのリポジトリの `main` を連携する。
2. サイトの **Project configuration → Environment variables** に `GAINA_ADMIN_KEY` を追加する。Functionsから参照できるスコープ・本番コンテキストに設定する。24文字以上の十分にランダムなキーを使う。画面の「接続設定 → 管理キーを生成してコピー」でも生成可能。
3. 環境変数設定後に本番を再デプロイする。
4. `/procurement/workspace.html` の「接続設定」に同じキーを入力する。チャットやリポジトリにはキーを載せない。
5. 現在の案件を「クラウドに保存」する。

Netlify BlobsはNetlify実行環境から注入されるサイト認証を利用します。通常、別のDBトークンは不要です。Blobs・Scheduled Functionsの利用可否、利用枠・課金はNetlifyのサイト設定で確認してください。`/api/procurement/status` はキー設定の有無だけを返し、管理APIと案件データは管理キーで保護します。

管理キーはタブのsessionStorageにのみ保存し、JSONバックアップには含めません。現バージョンは単一組織・共有管理キー・1つのクラウド案件を想定しています。ユーザーごとのログイン・権限分離・複数案件DBは未対応です。複数端末の同時編集は版番号とBlobsの条件付き書込で競合を検出します。競合時はバックアップしてからクラウドを再読込してください。

## 代理店へのURL依頼

「相見積依頼を作成」で代理店名を1行に1社、回答期限・仕様を指定します。発行した各社専用URLをコピーして、利用者からメール等で送信してください。このアプリからの自動メール送信は行いません。

- 各依頼に192ビットのランダムなトークンを発行し、専用URLのフラグメントで渡す。URLから読み込んだ後はアドレスからトークンを除く。
- 表示内容は依頼先・案件名・型番・数量・仕様だけ。売価・他社回答・掛け率・過去仕入額は渡さない。
- 代理店は税抜単価、納期、送料、有効期限、対応不可、担当者・備考を入力。回答期限内は再回答可能。
- 管理画面は表示中30秒ごとに回答を確認する。回答内容を確認して比較表へ反映し、クラウド保存する。
- 案件名・型番・数量が依頼時と違う場合、見積期限切れ、未対応品目がある場合は反映しない。
- 依頼URLは停止可能。期限切れ・停止済みの依頼には回答できない。
- URLを持つ人は回答できるため、取引先専用に共有する。氏名等の個人情報は必要最小限にする。

## 仕入履歴の取込・分析

CSV（UTF-8/Shift-JIS）、Excel `.xlsx` の先頭シートを読み込みます。先頭行を見出しとし、日付・仕入先・メーカー・型番・単価・数量などの列を対応付けてからプレビューします。

- 有効行・エラー行・重複行を区別。エラー行はスキップし、再取込時の完全一致データは除外。
- 同一メーカー・型番を全半角・空白・大文字小文字を正規化して集計。
- 直近、最安、中央値、数量加重平均、月別総額、仕入先構成を表示。
- 1ファイル10MB・3万行まで。独自の帳票レイアウト、複数の見出し行、PDFの仕入履歴、旧形式 `.xls` は未対応。
- JSONバックアップ・復元、分析CSV出力に対応。ブラウザ取込後は必要に応じてクラウド保存する。

単価差が仕様・数量・送料・時期によるものかは人が照合します。過去実績は上書きせず、定価改定前の基準を残します。

## メーカーの価格改定

「価格改定情報 → 収集元を登録」でメーカーを選択するか、公式ニュース一覧・RSSを指定します。メーカー候補は公式サイトの入口です。価格改定が載る一覧/RSSへURLを調整し、「今すぐ確認」で取得成功と検知件数を確認してください。

本番Scheduled Functionは **毎日9:00・15:00（日本時間）** に取得します。RSS/HTMLの価格関連リンクを検知し、案内URL・取得日時・取得結果を保存。失敗時はエラーを表示し、値を捏造しません。リンク本文の収集であり、PDF本文やJavaScript描画された情報の自動理解には対応していません。認証・有料データへのアクセスを回避しません。取得元の利用条件に従ってください。

1. 公式案内で対象型番・新定価・適用日を確認する。
2. 「改定を承認・予約」で対象商品のチェックを入れ、新定価と適用日を指定する。
3. 適用日以降、定期実行またはクラウド読込時に承認済みのクラウド案件へ反映する。
4. 予約時から定価・メーカー・型番が変わっていれば競合として記録し、自動上書きしない。

売価・入力済みの実見積単価・仕入実績は据え置き。掛け率による仮単価だけ再計算します。未承認の公式発表からの無条件な自動改定は行いません。予約と反映結果はクラウドへ記録します。

## 銅ベース

国内銅建値とLMEを別系列とし、情報元・通貨・単位が同じ記録だけで推移を比較します。円/t、円/kg、USD/tの自動換算・為替換算は行いません。

- 公式資料を確認した値の手動登録に対応。
- 自動数値取得は、公式HTMLの数値だけを含むCSS要素と `YYYY-MM-DD` の基準日要素を設定して利用。取得値・日付が曖昧なら保存せずエラーにする。
- 一般的なニュースリンク監視だけでは建値の数値は取得できません。公式サイトごとの形式に応じた設定・取得検証が必要です。
- 原価シミュレーションは銅比率を使う概算で、メーカー固有の銅ベーススライド式ではありません。仕入価格へは自動反映しません。

## 配線指示書

サンプル図面との位置連携、手動追加・編集、確認済み管理、色別CSV、職人用の施工・照合欄付き帳票、HTML保存・印刷/PDF保存に対応。アップロードした図面の自動OCR・接続解析は未実装。図面は外部送信せず再読込後は再選択が必要です。サンプル図面・金額は実施工・発注に使わないでください。

## 検証範囲

`npm test` はドメイン・API・収集処理とデモ・仕入分析計算の30ケースを実行。HTML/RSS/銅価格はフィクスチャによる解析検証です。公式Blobs SDK＋エミュレーターと実ブラウザで、クラウド保存、履歴取込、代理店URL発行、別画面の回答、比較表反映、承認価格の反映を通し検証しています。

実メーカーサイトの収集、公開Netlify上の定期実行、実代理店への送信・回答、本番Blobsの永続保存は別途本番で確認が必要です。開発環境の通信制限で公式サイトと公開NetlifyへのHTTPアクセスが拒否されている場合、公開状態を確認したとは扱いません。
